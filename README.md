# LAB-9：文件系统（文件管理与全系统整合）实验报告

## 一、过程性日志（按测试点与模块推进）

本实验并非一次性完成，而是围绕测试点逐步补全系统能力，整体推进过程如下。

### （一）基础准备与内存支持

- 实现 `pmem_stat`，用于统计内核空间与用户空间的空闲页数  
- 修改 `uvm_heap_grow`，使其支持传入内存权限标志  
- 引入行缓冲控制台抽象，统一 stdin / stdout 的输入输出行为  

**目的**：  
为后续 `/dev/gpt0` 设备文件与系统级测试提供底层支持。

---

### （二）目录与路径系统补全（test_2 相关）

完成 `dentry.c` 中缺失的核心逻辑，包括：

- 目录项遍历与搜索
- inode → path 的反向路径解析
- 基于路径的 inode 创建
- 硬链接（link / unlink）

此阶段重点解决的问题是：  
> **如何只依赖目录结构本身完成路径解析，而不额外维护路径缓存**

---

### （三）文件抽象引入（test_3 相关）

在 `fs.c` 中正式引入 `file` 抽象层，实现：

- inode 与进程的解耦
- 每个进程独立维护读写偏移
- 文件引用计数与生命周期管理

并完成 open / read / write / lseek / dup / close 等完整文件接口。

---

### （四）设备文件实现（test_3 / test_4）

实现 `/dev` 目录下的特殊文件：

- stdin / stdout / stderr  
- zero / null  
- gpt0  

设备文件不再走磁盘读写路径，而是通过 `device.c` 中的分发表直接处理。

---

### （五）进程与文件系统整合（test_4）

在进程结构体中加入：

- 打开文件表 `open_file[]`
- 当前工作目录 `cwd`

并在以下阶段维护其生命周期：

- 进程创建
- fork 继承
- exit 释放

---

### （六）ELF 执行与系统调用整合（test_4）

实现 `proc_exec`，将文件系统、内存系统、进程系统真正串联起来，使用户程序可以：

fork → exec → 运行 ELF → 使用文件系统 → 正常退出

## 二、与上一个实验相比的新增功能与整体理解

### 1️⃣ 新增的核心能力

相较 LAB-8，本实验新增了：

* **file 抽象层**（而不仅仅是 inode）
* **进程级文件描述符管理**
* **设备文件机制**
* **fork + exec 的完整程序执行模型**
* **统一的文件系统相关系统调用接口**

LAB-8 解决的是“磁盘数据如何组织”，
LAB-9 解决的是“进程如何使用这些数据”。

---

### 2️⃣ 各模块之间的逻辑关系

整个系统在 LAB-9 中形成了清晰的分层结构：

用户程序
   ↓
系统调用（syscall / sysfunc）
   ↓
file 抽象层（fs.c）
   ↓
inode / dentry / device
   ↓
磁盘 or 设备


* **file** 是进程视角的“文件”
* **inode** 是系统视角的“数据”
* **device** 是对“一切皆文件”的扩展

## 三、关键复杂逻辑说明（图示）

### 1️⃣ 路径解析（反向路径 inode → path）

通过 `..` 目录项逐层回溯父目录：

/root
 └── home
     └── user
         └── file.txt   ← 当前 inode
```

反向解析过程：

file.txt
   ↑ (..)
 user
   ↑ (..)
 home
   ↑ (..)
 root
```

路径字符串从缓冲区尾部向前构造，最终得到绝对路径。

---

### 2️⃣ file 与 inode 的关系

          inode (磁盘唯一)
               ↑
     ┌─────────┼─────────┐
     │         │         │
   file      file      file
 (proc A)  (proc B)  (proc C)


* inode 负责数据的持久化
* file 负责：

  * 权限
  * 偏移量
  * 引用计数

这使得多个进程可以**同时独立访问同一文件**。

---

### 3️⃣ exec 的整体流程

旧进程
  │
  ├─ fork → 壳进程
  │
  └─ exec：
       1. 解析 ELF inode
       2. 加载段到新页表
       3. 构造用户栈
       4. 切换地址空间
       5. 跳转到用户入口


exec 是本实验中**系统性最强的一步**，横跨：

* 文件系统
* 内存管理
* 进程控制

---

## 四、实验带给我的思考

1. **file 的引入是文件系统真正“可用”的关键**
   仅有 inode，进程无法独立、安全地操作文件。

2. **路径解析的本质是目录结构遍历，而不是字符串处理**
   所有路径问题最终都会落到 dentry 上。

3. **exec 是 OS 内核复杂度的集中体现**
   它不是单一模块的工作，而是系统整体协作的结果。

4. “一切皆文件”并不是口号，而是一种高度统一的设计哲学。
