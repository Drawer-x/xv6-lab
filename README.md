# LAB-6: 单进程走向多进程——进程调度与生命周期

## 1. 实验概览

### 1.1 实验目标
本次实验旨在实现操作系统的多进程管理，主要包括：
- **进程调度**：多个进程竞争CPU资源时的调度机制
- **生命周期管理**：进程的创建、退出、回收等完整生命周期
- **进程同步**：通过睡眠/唤醒机制实现进程间的协调

### 1.2 新增功能概览
相比上一个实验（LAB-5），本实验主要增加了：

| 功能模块 | 描述 |
|---------|------|
| 进程数组管理 | 支持最多N_PROC个进程同时存在 |
| 进程调度器 | 基于时间片的轮转调度 |
| fork/exit/wait | 进程创建、退出、等待机制 |
| sleep/wakeup | 进程睡眠唤醒机制 |
| 睡眠锁 | 基于睡眠唤醒的锁机制 |
| 抢占式调度 | 时钟中断触发的强制调度 |

## 2. 实现过程

### 2.1 进程数组管理（proc_init/proc_alloc/proc_free）

#### 进程状态机设计
![](/pictures/进程状态机设计.png)

**关键实现**：
- `proc_init()`: 初始化进程数组，全局PID计数器设置为1
- `proc_alloc()`: 从进程数组中分配空闲进程结构体，完成trapframe、页表、内核栈等初始化
- `proc_free()`: 回收进程资源，包括页表、trapframe、mmap区域等

### 2.2 进程调度器

#### 调度逻辑流程图
![](/pictures/调度逻辑流程图.png)

**关键实现**：
- `proc_scheduler()`: 调度器主循环，循环扫描RUNNABLE进程
- `proc_sched()`: 进程主动放弃CPU，切换到调度器上下文
- `proc_yield()`: 时钟中断触发时强制进程放弃CPU

### 2.3 进程生命周期管理

#### fork复制过程
```
父进程状态:
    ┌─────────────┐
    │ 代码段      │
    │ 数据段      │
    │ 堆区        │
    │ 栈区        │
    │ mmap区域    │
    └─────────────┘
         ↓ 复制
子进程状态:
    ┌─────────────┐
    │ 代码段(拷贝) │
    │ 数据段(拷贝) │
    │ 堆区(拷贝)  │
    │ 栈区(拷贝)  │
    │ mmap(拷贝)  │
    │ PID=新      │
    │ 返回0       │
    └─────────────┘
```

**关键实现**：
- `proc_fork()`: 复制父进程的页表、堆栈、mmap等状态
- `proc_exit()`: 设置ZOMBIE状态，唤醒父进程，资源由父进程回收
- `proc_wait()`: 父进程循环检查子进程状态，发现ZOMBIE则回收

### 2.4 睡眠/唤醒机制

#### proc_sleep/proc_wakeup工作原理
```
进程A: RUNNING → 需要资源 → SLEEPING (等待资源X)
进程B: 持有资源X → 释放资源X → 调用proc_wakeup(X)
进程A: 被唤醒 → RUNNABLE → 获取资源X → RUNNING
```

**关键实现**：
- `proc_sleep()`: 设置sleep_space，进入SLEEPING状态
- `proc_wakeup()`: 唤醒所有等待特定sleep_space的进程
- `proc_try_wakeup()`: 专门用于唤醒等待子进程退出的父进程

### 2.5 睡眠锁实现

**睡眠锁结构**：
```c
typedef struct {
    spinlock_t lock;    // 内部保护锁
    int locked;         // 锁状态
    char *name;         // 锁名
    int pid;            // 持有者PID
} sleeplock_t;
```

**工作流程**：
1. 尝试获取锁时，如果锁已被占用，进程进入睡眠
2. 锁释放时，唤醒所有等待该锁的进程
3. 相比自旋锁，睡眠锁适合保护长期持有的资源

## 3. 核心机制解析

### 3.1 调度器的工作原理

**调度器的双重角色**：
1. **上下文缓冲区**：在用户进程间切换时，调度器作为中间过渡
2. **进程选择器**：决定下一个运行的进程

**关键代码路径**：
```c
proc_scheduler() → 找到RUNNABLE进程 → swtch() → 用户进程
用户进程 → proc_sched() → swtch() → proc_scheduler()
```

### 3.2 进程状态转换

**五种状态的详细转换**：
1. **UNUSED ↔ RUNNABLE**：通过proc_alloc/proc_free
2. **RUNNABLE ↔ RUNNING**：通过调度器选择
3. **RUNNING ↔ SLEEPING**：通过proc_sleep/proc_wakeup
4. **RUNNING → ZOMBIE**：通过proc_exit
5. **ZOMBIE → UNUSED**：通过父进程proc_wait回收

### 3.3 页表复制机制

**fork时的页表复制**：
- 使用`uvm_copy_pgtbl()`复制父进程页表
- 为新进程分配独立的物理页
- 保持虚拟地址空间的一致性
- 父进程和子进程拥有独立的物理内存

### 3.4 时钟中断与抢占

**抢占时机**：
- 用户态时钟中断处理完成后
- 内核态时钟中断处理完成后
- 每次中断后检查是否需要调度

**抢占实现**：
```c
// 在timer_interrupt_handler()中
if (p != NULL && p->state == RUNNING) {
    proc_yield();  // 强制进程放弃CPU
}
```

## 5. 思考与总结

### 5.1 本次实验的关键收获

**进程调度的本质**：
- 调度器本身是一个特殊的"进程"，只是永不返回
- 通过两次`swtch()`完成用户进程间的切换
- 时钟中断提供了强制调度的能力

**资源回收的重要性**：
- 进程不能自我回收（无法给自己办葬礼）
- 父进程负责回收子进程，形成责任链
- 孤儿进程由proczero收养，避免资源泄漏

**同步机制的选择**：
- 自旋锁：短期等待，忙等策略
- 睡眠锁：长期等待，睡眠策略
- 根据等待时间选择合适的同步机制

### 5.2 陷阱机制的作用

**陷阱作为内核入口**：
1. **系统调用**：用户主动请求内核服务
2. **中断处理**：外部事件触发内核响应
3. **异常处理**：错误情况的统一处理

**陷阱的双向转换**：
- 用户态→内核态：保存用户上下文
- 内核态→用户态：恢复用户上下文
- 通过trampoline实现安全过渡

### 5.3 实验难点与解决方案

#### 难点1：进程上下文切换
**问题**：如何保存和恢复进程的执行状态？
**解决方案**：
- 定义完整的`context_t`结构体保存寄存器
- 通过`swtch.S`汇编实现上下文保存/恢复
- 调度器作为上下文切换的"中间人"

#### 难点2：睡眠唤醒的原子性
**问题**：如何避免睡眠和唤醒之间的竞争条件？
**解决方案**：
- `proc_sleep()`传入资源锁，保证设置状态和释放锁的原子性
- 唤醒时检查sleep_space的一致性
- 使用进程锁保护状态字段

#### 难点3：页表复制优化
**问题**：fork时完全复制页表效率低下
**解决方案**：
- 当前：完全复制物理页
- 优化方向：写时复制（Copy-on-Write）
- 延迟分配策略

### 5.4 实验总结

本次实验实现了操作系统的核心功能——多进程管理。通过构建完整的进程生命周期管理系统，深入理解了：

1. **进程调度的实现机制**：上下文切换、时间片轮转、抢占调度
2. **资源管理的设计原则**：父子关系、责任链、资源回收
3. **同步原语的实现**：自旋锁与睡眠锁的适用场景
